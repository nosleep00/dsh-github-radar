# 发布与上架 / Release & market listing

维护者文档：把仓库推到 GitHub、让插件出现在 DSH 插件市场（dshmarket）。
当前目标仓库：`https://github.com/nosleep00/dsh-github-radar`。

## 0. 发布前隐私自检

```bash
node scripts/audit-privacy.mjs        # 路径 / 邮箱 / 会话 ID / 密钥
node scripts/grep-any.mjs . "Users[/\\]+[A-Za-z0-9._-]+"
git log --all --format='%an <%ae> %cn <%ce>'   # 应只有中性身份
git ls-files | wc -l
```

要求：

- 提交作者是中性身份：`dsh-github-radar contributors <noreply@users.noreply.github.com>`。
  本地 `.git/config` 已固定成这个身份，历史也在发布前重建过（旧历史留在
  `~/.dsh/backup/dsh-github-radar-history.bundle`，含旧作者信息，**不要上传**）。
- 仓库里没有 `C:\Users\<你>`、工作区绝对路径、会话 ID、令牌。
- 文档里的示例路径统一写成 `$DSH_HOME`、`<repo>`。

## 1. 建 GitHub 仓库并推送

在 GitHub 上建一个**空**仓库 `nosleep00/dsh-github-radar`（不要勾选 README / .gitignore / license），
然后在本目录执行：

```bash
git remote add origin https://github.com/nosleep00/dsh-github-radar.git
git push -u origin main
git push origin v0.1.0
```

推送后到仓库的 **Settings → General → Topics** 加上：`dsh-plugin`（收录要求）、`dsh`、`deepseek-harness`。

> 需要你的 GitHub 凭据（HTTPS 口令 / 浏览器登录 / `gh auth login`）。这个目录里的提交作者已经是中性身份，
> 但**推送账号**仍是你自己——推送成功不代表泄露邮箱，GitHub 只展示我们提交里的 `noreply` 地址。

## 2. npm（可选，本次不做）

市场详情页会显示下载量，安装也更快；但收录与安装都不依赖它。

```bash
npm login
npm publish --access public
```

发布前确认 `package.json` 的 `files` 包含 `dist`、`client`、`cordis.patch.yml`、`locale`、`icon.svg`、`assets`、`screenshots.json`。
`repository` 字段必须指回上面那个仓库，市场的 npm 映射才会关联。

## 3. 提交市场收录

目录来自策展仓库 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)：
**一个 PR，只加一个文件**，站点与市场自动收录（通常一天内）。

要加的文件：`data/plugins/nosleep00__dsh-github-radar.yml`，内容就是本仓库的
[`docs/market-entry.yml`](market-entry.yml)：

```yaml
url: https://github.com/nosleep00/dsh-github-radar
name: nosleep00/dsh-github-radar
category: ui
icon: https://raw.githubusercontent.com/nosleep00/dsh-github-radar/main/assets/icon-180.png
description:
  en: 'A right-sidebar radar that turns the current session into five relevant GitHub repositories, …'
  zh: '右栏雷达：把当前会话变成五张 GitHub 项目卡片，……'
```

操作（GitHub 网页也能做）：

```bash
gh repo fork awesome-dsh-plugin/awesome-dsh-plugin --clone
cd awesome-dsh-plugin
cp /path/to/dsh-github-radar/docs/market-entry.yml data/plugins/nosleep00__dsh-github-radar.yml
git checkout -b add-dsh-github-radar
git add data/plugins/nosleep00__dsh-github-radar.yml
git commit -m "Add dsh-github-radar"
gh pr create --title "Add dsh-github-radar" --body "Right-sidebar GitHub recommendations for the current session."
```

要点（来自该仓库的 contributing.md）：

- 只有 `description.en` 必填；描述必须属实、不带营销词；含 `: ` 时必须加引号。
- 仓库要声明 `dsh.bundle`（本仓库有）、有真实代码、创建满 1 天、带 `dsh-plugin` topic、处于活跃维护。
- 图标必须是 GitHub 托管的**位图**（`assets/icon-180.png` 已生成；SVG 会被拒）。
- 截图在**自己仓库**里声明：本仓库根目录的 `screenshots.json`（1–8 张，相对路径）。

## 4. 验证

1. 市场里搜 `github-radar`：确认标题、`ui` 分类、中英描述、图标与截图正确。
2. 在一个干净 profile 里装一次：
   ```bash
   cd ~/.dsh/profiles/<干净的 profile>
   pnpm add github:nosleep00/dsh-github-radar
   # package.json → dsh.profile.bundles 追加 dsh-github-radar
   ```
   确认右栏出现「GitHub 雷达」，能出卡片。
3. 匿名额度下连点两次 `⟳` 会触发限速提示（预期行为，文案应可读）。

## 5. 版本与更新

- 改功能：更新 `CHANGELOG.md` + `package.json` 版本 + `git tag vX.Y.Z`；如果发了 npm 就再 `npm publish`。
- 市场条目不用跟着改版本：npm 版本或 pinned commit 由市场自己检查。
- 仓库改名/迁移：到 awesome-dsh-plugin 提 PR 改 `url` 与文件名。
