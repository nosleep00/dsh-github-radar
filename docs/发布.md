# 发布与上架 / Release & market listing

这份文档是给维护者用的：把一个干净的仓库推到 GitHub、可选地发到 npm，然后让插件出现在
DSH 插件市场（dshmarket）里。

## 0. 发布前隐私自检

```bash
node scripts/audit-privacy.mjs      # 路径 / 邮箱 / 会话 ID / 密钥
node scripts/grep-any.mjs . "Users[/\\]+[A-Za-z0-9._-]+"
git log --format='%an <%ae>'        # 作者身份（应当只有中性身份）
```

要求：

- 提交作者是中性的（例如 `dsh-github-radar contributors <noreply@users.noreply.github.com>`），
  不能出现真实姓名或个人邮箱。
- 仓库里没有 `C:\Users\<你>`、工作区绝对路径、会话 ID、令牌。
- 文档里的示例路径统一写成 `$DSH_HOME`、`<repo>`。

## 1. 建 GitHub 仓库并推送

仓库名建议就叫 `dsh-github-radar`（市场条目与仓库名一致，安装命令更直观）。

```bash
# 在 GitHub 上建一个空仓库 owner/dsh-github-radar，然后：
git remote add origin https://github.com/<owner>/dsh-github-radar.git
git push -u origin main
git push origin v0.1.0
```

推送后到仓库设置里加上 topic：`dsh-plugin`（市场收录要求），顺手加 `deepseek-harness`、`dsh`。

## 2. 发 npm（可选，但推荐）

市场安装优先级是「npm 包 > GitHub Release 预构建包 > 整仓源码」；源码安装最慢也最容易出问题。
`dist/` 已经随仓库提交，npm 发布只需要：

```bash
npm login                      # 需要一次性登录
npm publish --access public    # 包名 dsh-github-radar
```

发布前确认 `package.json` 里 `files` 包含 `dist`、`client`、`cordis.patch.yml`、`locale`、`icon.svg`。

## 3. 提交市场收录

插件市场（dshmarket）的目录来自策展仓库
[awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)：
**只需给那个仓库提一个 PR，加一个 YAML 文件**，站点与市场会自动收录（通常一天内）。

文件路径：`data/plugins/<owner>__<repo>.yml`，内容：

```yaml
url: https://github.com/<owner>/dsh-github-radar
name: <owner>/dsh-github-radar
category: ui
description:
  en: 'A right-sidebar radar that turns the current session into five relevant GitHub repositories, each with a one-line Chinese summary, the reason it was picked and an install command; falls back to recently active trending projects when the session has no signal yet.'
  zh: '右栏雷达：把当前会话变成五张 GitHub 项目卡片，每张都带一句中文摘要、推荐理由和安装命令；会话还没有线索时先给近期活跃的热门项目。'
```

要点（来自该仓库的 contributing.md）：

- 只有 `description.en` 是必填的；`zh` 可选，维护者会补。
- 描述里如果出现 `: `（冒号加空格）必须加引号；描述必须属实、不带营销词。
- 仓库必须声明 `dsh.bundle`（本仓库 `package.json` 里已有 `dsh.bundle.patch`）。
- 仓库要有真实代码、创建满 1 天、有 `dsh-plugin` topic、处于活跃维护状态。
- 可选 `icon: <GitHub 托管的位图 URL>`（PNG/JPEG，SVG 不作为商户卡片）；不写就用作者头像。

## 4. 验证

1. 市场里搜 `github-radar`，确认卡片标题、分类、中英文描述正确。
2. 在一个干净 profile 里装一次，确认右栏出现「GitHub 雷达」标签、能出卡片。
3. 匿名额度下连点两次 `⟳` 会不会触发限速提示（这是预期行为，文案要能看懂）。

## 5. 版本与更新

- 改功能：更新 `CHANGELOG.md` + `package.json` 版本 + `git tag vX.Y.Z`；npm 侧 `npm publish`。
- 市场条目不需要每次改版本：npm 版本或 pinned commit 由市场自己检查。
- 如果仓库改名/迁移：到 awesome-dsh-plugin 提 PR 改 `url` 与文件名。
